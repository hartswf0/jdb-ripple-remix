01Purpose + Core Problem
▶

Purpose: make influence perceptible inside an imaginary ecology. The aesthetic matters, but must serve legibility.

Show what changed in the source entity.
Show which other entities were affected, by what channel, and with what delay.
Show what resisted or failed to change.
Generate prose from the event record, not from mood alone.

Failure mode to avoid: atmosphere, texture, and motion that imply a ripple without exposing the transfer.

02Event Pipeline (Beta)
▶
  1. Select source entity and vector (GOAL / OBSTACLE / SHIFT).
  2. Compute source delta (before/after + explicit dimensions).
  3. Traverse relations (neighbors, attenuation, resistance, optional 2nd hop).
  4. Record transfers + non-effects in the audit log.
  5. Render visual impact (source, edges, targets).
  6. Generate worldtext from the recorded event.
  7. Suggest the next operator move.
Rule: If the prose cannot point to specific deltas, channels, delays, or blocked paths, the event is underspecified.
03Ontology (Entity / Vector / Edge / Evidence)
▶

Entity: holds mutable state; can receive perturbation; can affect or resist others; can be described from a perspective.

Vector: a perturbation class, not a prose style tag. It must produce explicit state deltas.

Edge: transfer relation with coupling, channels[], delayMs, resistance.

Evidence Statement: what changed, where, how much, because of what, with what delay, and what blocked it.

Entity state dimensions can be poetic, but they must remain stable and auditable (e.g. activity, stability, exposure, resource, signal).
04Prompt Architecture (A-E)
▶
  • Layer A — Entity Seed: entity × vector (scenario-specific baseline writing).
  • Layer B — Edge Prompt: source + vector -> target (channel, first visible change, delay, resistance).
  • Layer C — Propagation Prompt: chain/multi-hop traces (A -> B -> C).
  • Layer D — Counterfactual / No-Effect: why a path failed and what would be required for visibility.
  • Layer E — Audit Prompt: evidence-speaking prose generated from the structured event log.

Do not ship with generic placeholders as the primary prompt substrate. Author high-value edges first.

05ANGEL TRACE (PROMP-C) — Perspective Orchestration
▶

Dual Lens Method

Angel Lens: traces the ripple across the system. Mask Lens: returns the world through the selected entity’s perspective. Keep both lenses active.

Recursive Therefore Chain

L0 Stone → L1 Immediate Material → L2 Edge Transfers → L3 Field Consequence → L4 Mask Consequence. No leapfrogging.

Fracture Extraction

Locate where field-level pressure (resources / leverage / constraint) crushes or reroutes the chosen entity’s lived perspective. That fracture point is the narrative ignition point.
